# AI 落地实践 · 演讲技巧与页间承接

这场演讲最重要的技巧不是“讲得燃”，而是让听众一路觉得：我也能做，而且知道下一步怎么做。

可以把它当成三层结构来讲：

1. 认知拉齐：P01-P05
   让大家意识到，AI 编程不是“写代码更快”，而是“表达意图 + 做判断”。

2. 方法落地：P06-P10
   给工具、流程、案例，让听众知道第一步怎么做。

3. 边界升级：P11-P15
   从个人项目推到企业落地，再收回到个人行动。

## 演讲技巧

### 1. 少解释概念，多讲判断

不要长篇解释 Vibe Coding，可以说：

> 我理解的 Vibe Coding，不是一个新名词，而是你能不能用大白话把想做的东西说清楚。

这样更像真人分享，不像百科定义。

### 2. 每页只打一个点

这套 PPT 每页视觉都很强，不用把页面上所有字都读完。每页抓一个主句：

- P02：速度不是瓶颈，判断才是。
- P04：规格里最值钱的是“不做什么”。
- P05：产品周期从以月计，变成以天计。
- P11：个人项目靠脑内上下文，企业项目必须显性化上下文。

### 3. 多用“我以前以为，后来发现”

这会让分享更可信，比如：

> 我以前也以为，AI 编程就是让它帮我补代码。后来发现，真正的变化不是补代码，而是我能不能把一个任务交代清楚。

### 4. 互动不要太正式

说话比较平，可以用轻互动，不要搞成培训现场：

> 大家可以想一下，你最近有没有一个想做但一直没开始的小工具？
> 不用举手，心里有一个就行。

这种互动不会打断节奏，但能把听众拉进来。

### 5. 案例讲“痛点 → 动作 → 结果”

clip-shot 不要先讲技术，先讲烦：

> 我每天截图、保存、上传、复制链接。一次三十秒，但每天重复很多次，就很烦。于是我就想，这件事能不能消掉。

这样比“我做了一个 macOS 工具”更有代入感。

## 每页之间怎么承接

### P01 → P02

在正式讲工具之前，我想先把一个误区放在前面。很多人以为 AI 的价值是更快，但我现在越来越觉得，真正重要的不是速度。

### P02 → P03

如果判断不清楚，会发生什么？最典型的结果就是，很多人连第一个产品都做不出来，卡在第 0 个。

### P03 → P04

那怎么从“想法很多但没开始”，变成真的做出来？我现在会用一个很简单的三段式。

### P04 → P05

这三段式背后，其实是一个更大的变化：我们的工作重心，正在从写代码，变成表达意图。

### P05 → P06

当你接受这个变化以后，下一个问题就来了：具体用什么工具？工具很多，但我建议不要从排行榜开始看。

### P06 → P07

工具选完以后，不代表产品就出来了。真正关键的是，你怎么把第一个产品跑完。我一般把它拆成五步。

### P07 → P08

前面这五步，已经足够做第一个产品。但如果你想让 AI 不只是写代码，而是接入真实工作流，就会用到几个进阶能力。

### P08 → P09

讲完方法，我们看一个最小的真实案例。这个案例不大，但它特别适合作为第一个产品的样子。

### P09 → P10

clip-shot 是一件小事做到极致。那如果项目变复杂，从一个小工具变成一个完整产品，会发生什么？我们看 landr。

### P10 → P11

到这里为止，都是个人项目或者小团队比较舒服的场景。但同一套方法进企业以后，问题会明显变多。

### P11 → P12

所以企业里不能只靠一句 prompt 开干。你需要把前面的 Vibe 和 Spec 再往前延伸，覆盖更长的流程。

### P12 → P13

这些听起来还是方法论，我们看两个真实项目。一个是从零开始，一个是老系统改造。

### P13 → P14

这两个项目给我的最大感受是，AI 的价值不是只在单次提效，而是会沉淀成下一次的资产。

### P14 → P15

所以最后我想把事情收回来。你不需要一下子做企业级项目，真正的起点还是本周做出第一个小工具。

## 最后一页收尾技巧

P15 不要急着结束。可以放慢一点：

> 如果今天只记住一句话，我希望是这句：
> 你不需要成为更快的程序员，你需要成为更清晰的判断者。

然后停一秒，再说：

> 谢谢大家。

这个停顿很重要。不要马上补解释。让最后一句落下去。
