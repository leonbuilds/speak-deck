# AI 落地实践：用 Vibe Coding 打造你的第 1–N 个产品

**讲者**：阿亮 · 与智行 YuZhiXing｜AI 工程化训练营
**时长**：约 40 分钟
**主线**：沿「做出一个产品」的真实路径走一遍 —— 0→1，再到 1→N
**贯穿案例**：clip-shot（最小工具）· notchi（0→1 完整产品）· landr（1→N 商业化）

---

## 开场（约 3 分钟）

大家好，我是阿亮，做「与智行」AI 工程化训练营，自己也是一线的 AI Agent 工程师。

今天我不打算给大家讲一堆工具名词和参数对比。我想讲的是一件更具体的事 —— **怎么真的用 AI 做出一个产品，并且让它活下去。**

为了不空谈，我把自己 GitHub 上的三个项目带来了，它们会贯穿全场：

- **clip-shot** —— 一个住在 Mac 菜单栏里的小工具，把剪贴板里的图片直接变成一个 Markdown 链接；
- **notchi** —— 一个住在 Mac 刘海下方的编程桌宠，被动可视化你的 AI token 用量；
- **landr** —— 一个 AI 求职 Agent，把找工作这件事拆成可被自动化的全链路。

它们分别代表一个产品的三种状态：**最小可用、从 0 到 1、从 1 到 N。**

为什么是现在讲这个？因为 2025 年 11 月，Claude Opus 4.6 和 GPT-5.2 发布，第一次在复杂重构任务上超过了人类专家的平均水平。从「代码补全」到「自主完成复杂任务」，整个行业只用了不到 100 天。这不是又一次工具升级，是范式换代 —— 用北大那份报告里的话说，我们正站在「编程革命的奇点时刻」。

今天的路线很简单：先做**认知准备**，看懂这场革命；然后走**从 0 到 1**、**从 1 到 N**；再聊**工具选型和避坑**；最后落到**怎么成为超级个体**。

记住一句话，它是今天所有内容的底座：**没有最好的工具，只有最适合你当下这一步的工具。**

---

## 第一部分 · 认知准备：看懂这场范式革命（约 6 分钟）

### 编程在被一次次重写

软件编程的历史，是一部「人手写代码的比重不断被压缩」的历史：手工时代 → 高级语言 → IDE 时代 → 云协作 → Copilot 时代 → 现在的 Agentic 时代。每一次工具跃迁，效率都不是线性增长，而是台阶式跳变。我们现在站在又一个指数级拐点上。

支撑这次拐点的，是三个底层突破：Transformer 架构成熟、上下文窗口在几年里涨了上百倍、大模型的推理能力发生质变。

### 四种编程范式，先看清你站在哪一层

这是今天最重要的一张「地图」，请记住这四个词：

1. **Copilot（辅助编程）**：AI 帮你补全代码片段，人类全程主导。
2. **Vibe Coding（氛围编程）**：你用自然语言描述 + 看着效果确认，快速把创意变成东西。
3. **SPEC Coding（规范编程）**：你写一份结构化、无歧义、带验收标准的需求文档给 AI，工程级严谨。
4. **Agentic Coding（智能代理编程）**：你设定目标，AI 自主规划、执行、验证、修复，跑完一整段闭环。

再往后还有一个未来形态，叫 ID Coding（意图编程），代码会逐渐「隐形」。但今天我只讲能立刻落地的两个：**Vibe 和 SPEC**。

### Vibe Coding 到底是什么

这个词是 OpenAI 的联合创始人 Karpathy 在 2025 年 2 月提出的，原话是「通过自然语言提示词和视觉确认的创造性流动」。三个关键词：**Feel（感觉）、Flow（心流）、Function（功能）**。

它的本质，是**编程民主化** —— 让创意不再被技术栈卡脖子，让没有技术背景的人，也能参与到软件创造里来。

### 你的角色，正在被改写

当 AI 能自主写代码，开发者就从「写代码的人」，变成三种新角色：**Reviewer（审核者）、Architect（架构师）、Commander（指挥官）**。一句话概括这个转变：从「人类驾驶、AI 辅助导航」，变成「人类设定目的地、AI 驾驶」。

说到这里我想插一句我自己的状态。我 GitHub 上那三个项目，我几乎没有一行一行去敲。我电脑里那个工作目录，名字直接就叫 `auto-agentic-coding`。我的做法是：**先写 SPEC，再设检查点，然后让 AI 编排着干。** notchi 那份规格文档的「作者」一栏，我写的是四个字 —— **「leon + AI 编排」。**

这就是角色转变最真实的样子：你的价值，从「How 怎么实现」，挪到了「What 做什么」和「Why 为什么」。

## 第二部分 · 从 0 → 1：打造你的第一个产品（约 10 分钟）

### 第一个产品，用 Vibe Coding 就够了

做第一个产品，不需要 SPEC，不需要架构图。你只需要做对三件事：

- **输入怎么说**：自然语言描述 + 截图 + 草图都行，模糊需求也能开始，比如「让交互更流畅一点」；
- **反馈怎么改**：实时预览、所见即所得，看着效果一点点调；
- **心态怎么想**：用产品经理、导演的心态 —— 重视创意表达，追求**快速验证**，而不是一上来就追求完美。

### 第一个产品适合做什么

偏前端、偏可视化、容错率高、能快速看到效果的东西最合适：前端 UI 还原、Landing Page、快速原型、数据可视化、各种小工具。第一个产品的目标不是赚钱，是**让你建立信心、积累手感**。

### 我的案例 A：clip-shot —— 解决自己痛点的最小产品

我天天写文档、写课件，有一个动作重复了无数遍：截了张图，要存成文件、上传到图床、再把链接拷回来。烦透了。

于是我让 AI 给我做了 **clip-shot** —— 一个 macOS 菜单栏小工具，用 Swift 写的，只做一件极小的事：**剪贴板里的图片，自动传到云端，直接给你一个 Markdown 链接。** 它背后的图床，就是我另一个仓库 img-oss，本质就是拿一个 GitHub 仓库当图片存储用。

这就是最典型的 0→1：**为了解决自己的一个真实痛点，造出第一个工具。** 注意，Swift 并不是我熟的语言 —— 但因为这个需求足够小、足够清晰，AI 几下就帮我跑通了。这就是 Vibe Coding 的魔力：**当需求小而明确，技术栈的陌生不再是门槛。**

### 我的案例 B：notchi 的诞生 —— 从一个念头到 v0.1.0

第二个项目 notchi，起点也是一个特别「Vibe」的念头：我一个人 coding 久了挺孤单的，我想要个「活物」在屏幕上陪我，顺便能让我瞄一眼今天烧了多少 token。

于是就有了 notchi —— 一个住在 Mac 刘海下方的 Live2D 编程桌宠，被动可视化你的 AI 编程工具的 token 用量和会话状态。

但是 —— 这次我没有直接开干。我把这个念头先写成了一份 SPEC.md。**「先写规格还是直接开干」，正是从 0→1 跨向 1→N 的分水岭**，这个我下一部分专门讲。

先说结果：notchi 的 MVP 我估算是 7 天工作量，到现在 102 次提交，2026 年 5 月 8 日发布了 v0.1.0。它的技术栈是 Tauri 2 + Rust + React 19 + TypeScript —— 一个我自己原本扛不动的多语言项目，靠 SPEC + AI 编排，一个人就推下来了。

### 0 → 1 实操四步心法

总结一下做第一个产品的心法：①把需求说清楚（自然语言+截图+草图）；②小步快跑、盯着实时预览；③先「能用」再「完美」；④快速上线，用真实反馈决定下一步 —— 而不是埋头自嗨。

## 第三部分 · 从 1 → N：让产品稳下来、做下去（约 11 分钟）

### 从 1 到 N，难在哪

第一个产品靠「氛围」就能成。但你要把它做大、做稳、做久，就会撞上真正的工程问题：代码质量不稳定、可维护性差、长程任务 hold 不住。

解法就一句话：**左手 Vibe 求快，右手 Spec 求稳。** 这是「超级个体」的两只手。

### 武器一：SPEC Coding —— 写给 AI 看的需求文档

SPEC Coding 的核心，是「写给 AI 看的、结构化、无歧义、带约束和验收标准的需求文档」。它最忌讳模糊描述 —— 不要写「优化一下性能」，要写「接口响应时间 ≤ 200ms，支持 100 QPS 并发」。

我直接拿 **notchi 的 SPEC.md** 给大家看，这份文档我是可以直接当模板用的，它包含：

- **一句话定义、目标用户、核心价值**；
- **「不做清单」** —— 明确写下 MVP 不做什么。这一条是整份文档里最值钱的，因为它在帮 AI、也帮你自己「划边界」；
- **v1 → v2 路线图**；
- **19 条验收场景 S1–S19**，用接近 EARS 的句式写，比如「当 Claude Code 写入新事件时，系统应在 5 秒内更新 token 计数」—— 这就是「验收标准」长什么样；
- **技术约束、技术栈决策**；
- **任务拆解**，每个阶段对应一个 PR 分支；
- 还有一份**变更记录**。

### 武器二：Agentic Coding —— 让 AI 自己跑完一段长路

Agentic Coding 有两大核心能力：一是**长程任务**（长上下文、项目级依赖分析、把大任务拆成子任务）；二是**自主闭环**，也就是 Plan-Act-Observe-Fix —— 规划、执行、观察、修复，自己循环。

在 notchi 里，我用了两个抓手把它落地：

- **人工检查点**：我的 SPEC.md 里设了 2 个人工检查点 —— 一个确认范围、一个确认技术栈。AI 跑到这里必须停下来等我拍板。这跟我自己沉淀的那套 agentic-coding 工作流是一脉相承的。
- **任务拆解到 PR 分支**：阶段 1、2、3 各自是一个独立的 `claude/phase-x` 分支，原子化、可回滚 —— 哪一段崩了，单独退回去就行。

### 我的核心案例：landr —— 把一个 vibe coding 想法做到上线、可维护、可商业化

第三个项目 landr，是我目前最完整的 1→N 案例。它是一个 AI 求职 Agent，把「找工作」拆成可被 LLM 自动化的全链路：**简历理解 → 岗位匹配 → 面试准备 → 智能投递。**

它为什么是 1→N 的范本？

- **它有 6 个 Agent 模块**：简历智能体、岗位智能体、匹配与重写、面试准备、申请追踪（一个 7 列拖拽看板）、多 LLM 适配层。
- **它不是 prompt 套壳，它处理了真实场景里的「脏活」**：岗位列表只有 18 个字的摘要怎么办？后台自动开标签页抓详情页的结构化数据。Boss 直聘的风控怎么躲？多平台的 JD 字段怎么对齐？—— 这些都内置了工程化方案。
- **它带一个 Chrome 浏览器扩展**：把「打开 Boss 直聘 → 收集岗位」这个原本 30 分钟的人工活，压到 1 分钟。
- **它的工程完整度**：Next.js 16 + Prisma + 6 个数据模型、多 LLM 适配（DeepSeek / Kimi / 通义千问任选）、API Key 用 AES-256 加密存储、Vitest 26+ 个单测加 Playwright 端到端测试、PM2 + 阿里云 ECS 部署、25 次提交、2 个进行中的 PR。
- **它的 Roadmap 里写死了「不做清单」**：明确不做「自动打招呼/自动投递」（碰风控红线），不做「帮你 P 简历」。把「不做什么」写进规格，是 SPEC 思维的延续。

landr 自己的项目定位写得很清楚：**用同一套「SPEC + 检查点 + Skills」的工程方法论，把一个 vibe coding 的想法，做到上线、可维护、可商业化。** 这句话，就是「从 1 到 N」的全部意义。

### 进阶武器箱

最后给一个进阶武器箱：Agent Skills（把你的标准作业流程固化成可复用的能力）、原子级 TODO 管理、子智能体并行。它们能让 AI 从一个一次性的「代码生成器」，升级成能持续干活、自我修复的「7×24 执行代理」。

## 第四部分 · 工具与避坑（约 6 分钟）

### 工具全景：五大阵营

工具年年变，但阵营理念相对稳定。记住五大阵营就够了：**终端派**（Claude Code）、**全能派**（OpenAI Codex）、**IDE 派**（Cursor、Google Antigravity）、**开源派**（OpenCode）、**中国力量**（Trae、Qoder、CodeBuddy）。先理解派系，再挑具体工具，你就不会被名词淹没。

### 选型决策框架：问自己四个问题

不知道选什么，就问这四个问题：**问流程**（你是想优化一个环节，还是重塑整个开发生命周期）、**问生态**（你是否绑定了某个云）、**问数据**（你的代码能不能离开内网）、**问团队**（大家是终端偏好还是 GUI 偏好）。四个问题答完，最适合你的工具组合自然就浮现了。

### 我真实踩过的三个坑

讲点实在的，我自己踩过的坑：

1. **AI 会逆向你的环境做决策，你得看得懂、留得下记录。** notchi 里 `rusqlite` 和 `tauri-plugin-sql` 因为底层都链接 sqlite 而冲突，AI 自己做了取舍 —— 我把这个决策记进了 CHANGELOG。AI 的决策过程，必须可追溯。
2. **工程「脏活」AI 不会自动帮你想到，你得在 SPEC 里写明白。** landr 的风控规避、JD 二次抓取、多平台字段对齐 —— 这些你不写进规格，AI 就不会做。
3. **资产授权、陌生语言这类隐性坑，要提前预判。** notchi 用了 Live2D 官方样例模型，上架前必须替换；clip-shot 用 Swift，是我不熟的语言 —— 这些都得在规划阶段就标出来。

### 行业层面的三个坑

再补充三个行业层面的风险，来自北大那份报告：**性能断崖**（顶尖工具在公开库成功率 70%+，但面对企业私有库只剩约 23%）、**维护成本飙升**（AI Slop 堆积，维护成本可达传统模式的 4 倍）、**技能萎缩与隐私合规**。

避坑心法三句话：关键逻辑人工审、核心代码可走本地、别让 AI 替你「忘掉」基本功。

## 第五部分 · 超级个体与收尾（约 4 分钟）

### 超级个体的四大核心能力

当代码生成变得像空气一样廉价，开发者会进化成「超级个体」。支撑超级个体的，是四种核心能力：**业务洞察力、价值设计能力、系统思维能力、伦理判断力。** 注意，这四个里没有一个是「写代码」。

### 从 How 回归 What 与 Why

人类的核心价值，正在收敛到两件事：**定义 What** —— 解决什么问题；**判断 Why** —— 为什么这么做。「人人都是产品经理」，在未来不是一句口号，是开发者生存的最低门票。

### 我的判断

回到我自己。我一个人，用同一套方法论，同时在推进 notchi、landr、clip-shot 三个技术栈完全不同的项目 —— Rust、TypeScript、Swift。这不是因为我代码写得多好，而是因为我把自己从「写代码」这个位置，挪到了「写 SPEC、设检查点、做编排」这个位置。

这就是超级个体真实的样子。给大家两条最实在的建议：

1. **本周就动手**，用 Vibe Coding 做出你的第一个产品 —— 哪怕它小得像 clip-shot 一样，只做一件事。
2. **给它写一份 SPEC**，用 SPEC + Agentic 的方法，让它能从 1 走到 N。

### 结束语

2026 年是 Agentic Coding 的元年。在这个奇点时刻，**谁先理解了角色转换，谁先学会了如何指挥那支由 AI 代理构成的「数字化军团」，谁就拿到了通往未来的船票。**

谢谢大家。
